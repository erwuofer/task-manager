# Дизайн-документ: Task Manager

## 1. Загальна інформація

**Назва проєкту:** Task Manager  
**Тип програми:** консольний застосунок для роботи зі списком завдань.  
**Мова програмування:** Java 21.  
**Система збірки:** Maven.

Програма призначена для ведення простого списку особистих завдань. Користувач може додавати завдання, переглядати їх, позначати виконаними та видаляти. Дані зберігаються у JSON-файлі, тому список залишається після завершення програми.

## 2. Можливості та вимоги

### Функціональні вимоги

- Перегляд усіх завдань зі статусом виконання.
- Перегляд докладної інформації про завдання за його номером.
- Створення завдання через послідовний діалог у консолі.
- Позначення завдання виконаним.
- Видалення завдання.
- Автоматичне збереження змін та відновлення даних під час наступного запуску.
- Виведення переліку доступних команд.

### Режими роботи

Під час запуску можна вибрати один із двох режимів CLI:

- **Перегляд** — доступні команди `list`, `show` та `help`.
- **Керування** — доступні всі команди, зокрема створення, завершення та видалення завдань.

Режим можна вибрати через діалог під час запуску або передати аргументом `--view` чи `--manage`.

## 3. Архітектура програми

Застосунок поділений на три основні частини: представлення, бізнес-логіку та збереження даних.

- **Presentation** — робота з командами, введенням і виведенням інформації.
- **Core** — модель завдання та правила роботи зі списком.
- **Data / Infrastructure** — читання і запис JSON-файлу, а також консольне введення та виведення.

`Main` створює потрібні об'єкти та зв'язує їх між собою. Шар Core не залежить від консолі або Gson. Він працює з інтерфейсом `TaskRepository`, а конкретну реалізацію цього інтерфейсу надає інфраструктурний шар.

## 4. Бізнес-логіка (CORE)

У Core знаходяться `Task` і `TaskService`. Вони не працюють безпосередньо з консоллю чи JSON. Для завантаження та збереження даних `TaskService` використовує інтерфейс `TaskRepository`.

### Модель завдання

Одне завдання містить такі поля:

| Поле          | Тип       | Опис                                |
|---------------|-----------|-------------------------------------|
| `id`          | `long`    | Додатний унікальний номер завдання. |
| `title`       | `String`  | Обов'язкова назва.                  |
| `description` | `String`  | Необов'язковий опис.                |
| `completed`   | `boolean` | Ознака виконання.                   |

### Правила роботи

- Номер завдання має бути більшим за нуль і не повторюватися в поточному списку.
- Нова назва очищається від пробілів на початку та в кінці й не може бути порожньою.
- Опис також очищається від зайвих пробілів. Якщо його не вказано, зберігається порожній рядок.
- Нове завдання завжди створюється зі статусом `completed = false`.
- Після завершення завдання його статус стає `true`. Повторне виконання цієї операції не змінює вже завершене завдання.
- Завершити або видалити можна лише завдання, яке є у списку.
- Після видалення інші завдання не перенумеровуються.
- Якщо збереження не вдалося, новий стан не підміняє поточний список у `TaskService`.

### Основні операції TaskService

| Метод                                      | Призначення                                                         |
|--------------------------------------------|---------------------------------------------------------------------|
| `findAll()`                                | Повертає незмінний список поточних завдань.                         |
| `findById(long id)`                        | Знаходить завдання за номером або повідомляє, що його немає.        |
| `create(String title, String description)` | Перевіряє дані, створює завдання з новим номером і зберігає список. |
| `complete(long id)`                        | Позначає знайдене завдання виконаним і зберігає список.             |
| `delete(long id)`                          | Видаляє знайдене завдання та зберігає список.                       |

### Послідовність зміни даних

Під час створення, завершення або видалення завдання `TaskService` спочатку готує копію списку з потрібною зміною. Потім передає її в `TaskRepository.save()`. Лише якщо збереження завершилося успішно, новий список стає поточним у сервісі.

`TaskRepository` оголошений у Core, але реалізований у Infrastructure. Завдяки цьому бізнес-логіка не залежить від конкретного формату збереження. Надалі JSON-сховище можна замінити іншою реалізацією, не змінюючи правила роботи із завданнями.

## 5. Основні класи

| Клас або інтерфейс   | Призначення                                                                                           |
|----------------------|-------------------------------------------------------------------------------------------------------|
| `Main`               | Створює об'єкти програми та реєструє команди.                                                         |
| `Command`            | Спільний інтерфейс консольних команд.                                                                 |
| `CommandParser`      | Розбирає введений рядок на назву команди, аргументи та опції. Підтримує лапки для тексту з пробілами. |
| `CommandRegistry`    | Зберігає зареєстровані команди та знаходить їх за назвою.                                             |
| `CommandLoop`        | Приймає команди в циклі, запускає їх та показує помилки.                                              |
| `ModeSelector`       | Вибирає режим через аргумент запуску або діалог.                                                      |
| `TaskMode`           | Позначає режими перегляду та керування.                                                               |
| `Task`               | Модель одного завдання та перевірка його основних даних.                                              |
| `TaskService`        | Виконує операції над завданнями та передає оновлений список на збереження.                            |
| `TaskRepository`     | Визначає операції завантаження та збереження списку завдань.                                          |
| `JsonTaskRepository` | Реалізує `TaskRepository` за допомогою Gson та JSON-файлу.                                            |
| `TaskPresenter`      | Організовує діалог із користувачем і форматує інформацію про завдання.                                |
| `ConsoleDisplay`     | Читає введення та виводить текст у консоль.                                                           |

Для команд використовується окремий клас на кожну дію. Це дозволяє додати нову команду через реалізацію `Command` і її реєстрацію в `Main`, не змінюючи цикл виконання.

## 6. Консольний інтерфейс

Якщо програму запустити без аргументів, вона запропонує вибрати режим. Також режим можна вказати під час запуску:

| Аргумент       | Режим                                    |
|----------------|------------------------------------------|
| `--view`       | Перегляд завдань без команд зміни даних. |
| `--manage`     | Повне керування списком завдань.         |
| без аргументів | Вибір режиму через діалог.               |

У режимі перегляду доступні `help`, `list`, `show` та `exit`. У режимі керування доступні всі команди з таблиці нижче.

| Команда       | Дія                                                                                             |
|---------------|-------------------------------------------------------------------------------------------------|
| `help`        | Показати доступні команди.                                                                      |
| `list`        | Вивести завдання. Підтримує фільтр `--status all`, `--status pending` або `--status completed`. |
| `add`         | Створити завдання через діалог.                                                                 |
| `show <id>`   | Вивести назву, опис і статус завдання.                                                          |
| `done <id>`   | Позначити завдання виконаним.                                                                   |
| `delete <id>` | Видалити завдання.                                                                              |
| `exit`        | Завершити програму.                                                                             |

## 7. Модель збереження даних

Файл `data/tasks.json` створюється автоматично під час першого збереження. Після створення, завершення або видалення завдання `TaskService` передає новий список до `TaskRepository`, а `JsonTaskRepository` записує його у файл. Під час запуску список завантажується з цього самого файлу. Якщо файлу ще немає, програма починає з порожнього списку.

## 8. Обробка помилок

Програма повідомляє користувача, якщо введено невідому команду, неправильну кількість аргументів, некоректний номер або номер завдання, якого немає у списку. Порожня назва не дозволяється. Помилки читання чи запису файлу також передаються користувачу. Якщо збереження не вдалося, `TaskService` залишає попередній список без змін.

## 9. Запуск і перевірка

Потрібні JDK 21 або новіший та Maven. Команди виконуються з кореневої папки проєкту:

```bash
mvn test
mvn exec:java
```

За потреби режим можна передати під час запуску:

```bash
mvn exec:java -Dexec.args="--view"
mvn exec:java -Dexec.args="--manage"
```

Тести перевіряють правила моделі `Task`, основні операції `TaskService`, обробку помилок збереження, читання та запис JSON, розбір команд, вибір режиму й спільний сценарій роботи CLI. Тимчасові файли тестів створюються в окремих тимчасових папках, тому тестування не змінює робочий файл `data/tasks.json`.
